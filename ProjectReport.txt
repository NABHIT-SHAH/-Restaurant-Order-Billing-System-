3. PROBLEM STATEMENT
--------------------------------------------------------------------------------
Traditional food service establishments frequently struggle with manual paper-based
order taking and billing. Common pain points include:
1. Calculation errors in subtotals, tax computation, and discount deductions.
2. Inefficient communication between dining staff and inventory/cashier counters.
3. Lack of accurate historical records for sales analysis and popular menu tracking.
4. Vulnerability to data loss and billing discrepancies during peak operating hours.

To resolve these challenges, the Restaurant Order & Billing System provides a robust,
modular, console-based desktop application written in C++17. The system automates
menu catalog maintenance, customer directory management, multi-item order placement,
automatic GST taxation and discounts, receipt generation, and persistent disk storage.


4. OBJECTIVES
--------------------------------------------------------------------------------
- Develop a modular, object-oriented software system in standard C++17.
- Implement strict encapsulation with private data members and public interfaces.
- Utilize inheritance and runtime polymorphism for specialized menu items.
- Implement dynamic memory allocation (new[] and delete[]) adhering to the Rule of Three.
- Implement reliable file handling to ensure complete data persistence across sessions.
- Provide a minimum 9-option interactive main menu with input validation and exception handling.
- Generate managerial reports summarizing revenue, taxes, discounts, and item tallies.


5. FEATURES AND MENU OPERATIONS
--------------------------------------------------------------------------------
The system features a structured menu-driven workflow:

Option 1: Add Record
  - Add specialized Food Items (with cuisine type and vegetarian flag).
  - Add specialized Beverage Items (with serving size and hot/cold indicator).
  - Register new Customers with mandatory 10-digit phone number validation.

Option 2: Display Records
  - Tabular polymorphic display of menu items showing ID, Name, Price, Category,
    Type-specific attributes, and Current Availability.
  - Formatted display of customer records, active/past orders, and generated bills.

Option 3: Search Record
  - Search menu items, customers, orders, and bills by ID or case-insensitive keyword.

Option 4: Update Record
  - Modify item price, category, name, or availability.
  - Modify customer contact details.
  - Update order workflow status (Pending, Completed, Cancelled).

Option 5: Delete Record
  - Delete menu items or customers with user confirmation and dynamic array realignment.

Option 6: Place Order (Main Transaction)
  - Interactive multi-step order placement:
    Step 1: Select existing customer or register new customer on-the-fly.
    Step 2: Display polymorphic menu items.
    Step 3: Dynamically add items and quantities to the Order object.
    Step 4: Display order summary and calculate subtotal.
    Step 5: Apply GST tax rate (default 18%) and flat discounts.
    Step 6: Instantiate Bill, calculate final total, and display formatted receipt.
    Step 7: Collect payment (Cash, Card, UPI), mark bill as Paid, and complete order.

Option 7: Generate Report
  - Displays system-wide counts, pending vs completed orders, total revenue,
    total GST collected, total discounts given, and top 3 popular ordered items.

Option 8: Save/Load Data
  - Manual on-demand persistence synchronization.

Option 9: Exit
  - Automatically saves all modified records to text files and safely terminates.

7. OOP CONCEPTS DEMONSTRATED WITH CODE EXAMPLES
--------------------------------------------------------------------------------
1. Classes and Objects:
   Each domain entity is modeled as a class. Real-world restaurant components
   (Food, Beverage, Customer, Order, Bill) are instantiated as objects during runtime.

2. Encapsulation:
   All attributes are declared private or protected. External access is mediated
   exclusively via public member functions and getters/setters.
   Example:
     class Customer {
     private:
         int customerId;
         string name, phone, address;
     public:
         string getName() const { return name; }
         void setName(const string& n) { name = n; }
     };

3. Constructors and Destructors:
   Default and parameterized constructors are implemented across all 8 classes.
   Destructors systematically release resources.
   Example:
     Order::Order(int orderId, int customerId) : orderId(orderId), customerId(customerId),
         itemCount(0), capacity(5), status("Pending") {
         itemIds = new int[capacity];
         quantities = new int[capacity];
     }
     Order::~Order() {
         delete[] itemIds;
         delete[] quantities;
     }

4. Inheritance:
   FoodItem and BeverageItem extend MenuItem, inheriting core properties while
   adding specialized domain fields (cuisineType, isVeg, size, isHot).
   Example:
     class FoodItem : public MenuItem {
     private:
         string cuisineType;
         bool isVeg;
     public:
         FoodItem(int id, string n, double p, string c, string cuisine, bool veg)
             : MenuItem(id, n, p, c), cuisineType(cuisine), isVeg(veg) {}
     };

5. Runtime Polymorphism:
   The Restaurant class stores pointers of base type MenuItem*:
     MenuItem** menuItems = new MenuItem*[capacity];
   When iterating, virtual methods dispatch dynamically at runtime based on the actual
   derived object type:
     menuItems[i]->display(); // Dispatches to FoodItem::display() or BeverageItem::display()

6. Dynamic Memory Management & Rule of Three:
   The Order class maintains dynamic arrays allocated on the free store with new[].
   To prevent double-deletion and pointer aliasing, the Rule of Three is strictly implemented:
     - Destructor: frees allocated memory
     - Copy Constructor: performs deep copying
     - Copy Assignment Operator: deallocates old buffers and deep-copies elements


8. FILE HANDLING AND DATA PERSISTENCE
--------------------------------------------------------------------------------
Data is persisted in the Data/ directory using standard pipe-delimited text files:
- Data/menu_items.txt : Stores FoodItem and BeverageItem records.
- Data/customers.txt  : Stores registered diner records.
- Data/orders.txt     : Stores orders and comma-separated item lists (id:qty).
- Data/bills.txt      : Stores billing receipts, taxes, discounts, and payment methods.

Persistence Workflow:
1. Application Start: loadData() invokes FileManager to parse files and reconstruct
   in-memory dynamic arrays.
2. In-Memory Processing: All additions, edits, deletions, and transactions mutate dynamic arrays.
3. Application Exit: saveData() serializes all records back to disk, preserving changes.
Verification: The application was tested by adding records, closing the binary, and
re-launching. All newly created records were accurately reloaded.

10. PROGRAM WORKFLOW
--------------------------------------------------------------------------------
1. Entry: main() instantiates Restaurant restaurant; and calls restaurant.run();
2. Startup: Restaurant invokes loadData(), populating dynamic arrays from disk.
3. Menu Loop: Displays the 9-option menu, accepts validated integer choice.
4. Branching: Dispatches to sub-menus (Add, Display, Search, Update, Delete),
   Main Transaction (Place Order), Report, or Save/Load.
5. Transaction: Places order, calculates billing with tax/discount, collects payment.
6. Termination: User selects option 9; saveData() flushes arrays to disk, destructors
   cleanly release all heap memory, and program exits safely with return code 0.

12. CHALLENGES AND SOLUTIONS
--------------------------------------------------------------------------------
Challenge 1: Object Slicing with Polymorphism
- Issue: Storing derived objects in value-type arrays slices off derived fields.
- Solution: Used an array of base class pointers (MenuItem**) in Restaurant and dynamically
  instantiated FoodItem or BeverageItem using new.

Challenge 2: Rule of Three Memory Management
- Issue: Default shallow copying of Order objects caused double-free errors on destruction.
- Solution: Explicitly implemented a deep-copy constructor, copy assignment operator,
  and destructor to manage the dynamically allocated itemIds and quantities arrays.

Challenge 3: C++ Stream Extraction and Buffer Overflow
- Issue: cin >> left trailing newline characters, causing subsequent getline() calls to fail.
- Solution: Used cin.ignore(numeric_limits<streamsize>::max(), '
') and cin.clear() across
  all input paths to ensure robust stream state recovery.

Challenge 4: Multi-Item Serialization
- Issue: Representing dynamic arrays of items and quantities inside a flat single-line record.
- Solution: Implemented nested string tokenization using stringstream, formatting item pairs
  as id1:qty1,id2:qty2 separated by commas within the pipe-delimited line.

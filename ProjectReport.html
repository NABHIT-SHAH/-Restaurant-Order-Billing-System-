3. Problem Statement

Manual restaurant management is prone to billing calculation errors, delays in food ordering, poor customer record keeping, and lack of automated sales analytics. This project provides a robust, object-oriented desktop application in C++ to automate table ordering, menu management, GST taxation, discounts, bill calculation, receipt printing, and complete file persistence.

4. Objectives

  • Apply core OOP principles: Classes & Objects, Encapsulation, Inheritance, Runtime Polymorphism, Dynamic Memory, and File Handling.
  • Implement dynamic memory management using new[] and delete[], fulfilling the Rule of Three.
  • Ensure bidirectional data persistence with pipe-delimited files.
  • Provide an interactive 9-option menu with defensive input validation and exception handling.
  • Generate statistical reports on revenue, taxes, discounts, and item popularity.

6. Classes and Responsibilities

  • MenuItem (Base): Abstract base class for menu items with virtual display, serialization, and getters/setters.
  • FoodItem (Derived): Extends MenuItem with cuisine type and vegetarian flag.
  • BeverageItem (Derived): Extends MenuItem with size and hot/cold indicator.
  • Customer: Manages customer directory with 10-digit phone number validation.
  • Order: Manages dynamic arrays (new int[capacity]) for item IDs and quantities with deep copy constructor, assignment operator, and destructor.
  • Bill: Calculates subtotal, GST (18%), discounts, and total amount. Generates formatted receipts.
  • FileManager: Handles pipe-delimited file reading and writing.
  • Restaurant: System coordinator managing dynamic polymorphic arrays, menu loops, and transactions.

7. OOP Concepts Used

  • Encapsulation: Private members with public getters/setters.
  • Constructors/Destructors: Default, parameterized, and deep-copy constructors across all classes.
  • Inheritance: FoodItem and BeverageItem publicly inherit from MenuItem.
  • Runtime Polymorphism: Base class pointer array MenuItem** dynamically dispatches virtual methods.
  • Dynamic Memory: Order uses int* itemIds = new int[capacity] and delete[] with Rule of Three.

8. File Handling

All data is persisted in Data/ via pipe-delimited records (menu_items.txt, customers.txt, orders.txt, bills.txt). Persistence was verified across multiple program restarts.
